## 🎯 Контекст и цель

Я хочу собрать **персональный трекер активности за ПК** с интеграцией Bitrix24 — чтобы автоматически сопоставлять мою работу (URL, приложения, окна) с задачами в CRM, визуализировать это в дашбордах и генерировать ежедневный отчёт для ИИ-анализа.

Приложение — **только для личного использования** (single-user), но архитектурно готово к локальному серверу и Mac-приложению.

---

## 🧱 Технический стек

- **Frontend:** React Native + Expo (для быстрой конвертации в macOS-приложение через `react-native-macos` или Electron-обёртку)
- **UI:** shadcn-подход + Tailwind (для RN — `nativewind` + порт shadcn-компонентов)
- **Backend:** локальный Node.js/Express-сервер (тот же код, что и в приложении)
- **Хранилище:** SQLite (локально, файл рядом с приложением)
- **Интеграции:** Bitrix24 REST API (через хуки из `.env`)
- **Экспорт:** Markdown-файлы + JSON для последующего ИИ-анализа

## 🏗 Архитектура (одна кодовая база, 2 режима запуска)

```
/app        → React Native (Expo) — UI + local server
/server     → Node.js API + SQLite + сборщик активности
/shared     → типы, утилиты, схемы БД
/scripts    → парсеры URL → задача, генератор отчётов
.env        → BITRIX_HOOK_USER, BITRIX_HOOK_AI (из @.env:1 и @.env:4)
```

Режимы:
1. **Local web** — `npm run dev` → localhost:3000
2. **macOS app** — `npm run build:mac` → .app через RN macOS / Electron

## ⚙️ Функциональные требования

### 1. Сбор активности (фон, macOS)
- Активное окно (заголовок, приложение)
- Активный URL из браузера (Chrome/Safari/Arc)
- Idle-детект (нет ввода > N сек → пауза)
- Хранение: `activity(id, ts_start, ts_end, app, url, title, duration)`

### 2. Интеграция Bitrix24 (через `@.env:1`)
- Подтягивать **задачи пользователя Андрей Родькин**
- Для каждой задачи: связанная сделка → её поле `WEB` (URL компании)
- Маппинг: `task_id ↔ company_url ↔ deals`
- Кэш задач локально, обновление раз в N минут

### 3. Матчинг активности → задачи
Алгоритм:
1. Если URL активности совпадает с `WEB` компании сделки → **auto-match (confidence high)**
2. Если домен совпадает → **suggested match**
3. Иначе → **unassigned**

### 4. Дашборд-вкладка №1 — «Обзор»
- Timeline активности за день (как в референсе)
- Графики: время по приложениям, по доменам, по задачам
- Карточка «Что я делал сегодня» — топ задач по времени
- Фильтры: день / неделя / месяц

### 5. Дашборд-вкладка №2 — «Матчинг»
- Список: **активность → предлагаемая задача** (с % уверенности)
- Группировка по домену (одна активность на сайте = одна строка)
- Кнопка **«Подтвердить»** — записать время в задачу
- Кнопка **«Раскидать всё»** — массовое назначение
- Ручное переопределение задачи для группы

### 6. Отчёты
- **Ежедневный автоотчёт в 17:40** по будням
- Формат: `.md` **без воды**, только структура
- Группировка по задачам, внутри — время, что делал, ссылки
- Сгенерированный текст уходит в `@.env:4` (ИИ-хук) для суммаризации
- Файлы: `./reports/YYYY-MM-DD.md`

Пример структуры отчёта:
```md
# Отчёт 2026-10-09 (Андрей Родькин)

## Задача #1423 — Внедрение CRM (ООО Ромашка)
- 09:12–10:40 (1ч28м) — crm.romashka.ru, настройка воронки
- 11:00–11:25 (25м) — docs.bitrix24.ru, изучение API

## Задача #1491 — Правки лендинга
- 14:00–15:10 (1ч10м) — figma.com, макеты

## Не назначено
- 12:00–12:30 — youtube.com
```

## ✅ Критерии готовности (Definition of Done)

- [ ] Приложение запускается как local server (`npm run dev`)
- [ ] Собирается в .app для macOS одной командой
- [ ] Активность пишется в SQLite и видна в UI
- [ ] Bitrix24 подтягивает задачи + поля `WEB` через `.env:1`
- [ ] Работает авто-матчинг URL → задача
- [ ] Есть 2 вкладки-дашборда с графиками и timeline
- [ ] В 17:40 формируется `reports/YYYY-MM-DD.md`
- [ ] Отчёт отправляется в ИИ через `.env:4` и обогащается

## 📝 Как пользоваться этим промптом

**Совет:** не грузи это всё одним сообщением. Разбей на этапы и проси LLM идти по фазам:

1. **Фаза 1:** инициализация проекта + local server + SQLite
2. **Фаза 2:** сборщик активности (macOS окна/URL)
3. **Фаза 3:** интеграция Bitrix24 + матчинг
4. **Фаза 4:** UI дашборд №1
5. **Фаза 5:** UI дашборд №2 + ручное назначение
6. **Фаза 6:** генератор отчётов + ИИ-хук
